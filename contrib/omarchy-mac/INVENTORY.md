# Inventory: every customization on the MacBook Pro J716s (M5 Pro) running Omarchy

Source of truth for `audit-macbook.sh`: every backticked absolute path (`/etc/...`, `~/.config/...`), `pkg:NAME` and `unit:NAME`
below counts as tracked; a trailing `/` covers a whole directory. Scope, status and upstream target are defined in `README.md`.
Dated 2026-11-17, kernel `7.3.0-gec5f49f167be`, Omarchy 4.5.0-3. Rows owned by another agent say so and are not edited here.

Short forms in "Install" / "Undo": `item X` = `sudo contrib/omarchy-mac/install-item.sh [--user NAME] [--remove] X` (see `README.md`);
"apply.sh" = `contrib/pending/desktop-defaults/apply.sh` (idempotent; picks the logged-in desktop user since commit 7481e52; it has no undo, so Undo lists the manual reverse).

## J. Looks wrong on the MacBook (found by the audit, not changed)

- Stale files left in system paths: `/usr/local/sbin/m5-selftest.bak`, `/usr/local/bin/hypr-gpu-session.pre-dcp`, `/etc/mesa-aurora/session.env.zink`, `/etc/mesa-aurora/session.env.native-20261108`, `/etc/pacman.conf.pre-quattro`, `/etc/ufw/after.rules-ufw-docker~...~` and the `after6` twin, `/usr/share/wireplumber/wireplumber.conf.d/99-asahi-j716.conf.j716-ab-orig` (an A/B backup inside a directory wireplumber reads), and `/usr/share/alsa/ucm2/conf.d/macaudio/MacBook Pro J716.conf.orig`.
- Four 71 MB Mesa trees (a fifth, `/opt/mesa-aurora-20261117`, is the side-by-side A/B tree; `/opt/mesa-aurora` is the one the session runs, commit `a79e5a94e316`, stock Arch `mesa` is only the software fallback and has no Vulkan driver): `/opt/mesa-aurora`, `/opt/mesa-aurora-gl`, `/opt/mesa-aurora-gl2`, `/opt/mesa-aurora.a8e86a80cdc`.
- Bring-up network files for systemd-networkd (`10-usb-gadget-*.network`, `20-wired.network`, `en.network`, `eth.network`): NetworkManager runs the network, so three overlapping wired-DHCP files are dead weight.
- `~/.config/hypr/` holds a dozen `*.bak`, `*.pre-*` and `*.orig-*` copies; `hypridle.conf` and `hyprlock.conf` there are leftovers of the lite desktop (Omarchy 4.5 uses its shell's idle service, not hypridle).
- Kernel, m1n1/aura and the boot guard are not pacman packages on the Mac (`pacman -Q linux-m5pro m1n1-m5pro m5pro-boot` finds nothing) although the PKGBUILDs exist.
- The alsa-ucm-conf-asahi package is installed but the J716 files in its directory are not owned by it (hand-copied over).
- The `kmlink` package and its plugin have no source repository: the source is `~/km-link-omarchy/` on the Mac, outside version control.
- `RebootWatchdogSec=5min` in `m5pro-watchdog.conf` is longer than the Apple SoC watchdog can count (about 178 s, per alarm-aurora's `aurora-system-fixes`, which uses 2 min): a stalled reboot is not reset for the full five minutes.
- `m5-fan-floor.service` is installed but its script is missing (harmless: the unit is disabled and gated on a kernel argument).
- `desktop-defaults/README.md` still says systemd-oomd is not started; it is active now (PSI is in this kernel).
- The Mac's `/etc/sudoers.d/50-asdcontrol` and Omarchy files are stock; nothing wrong, listed only because the audit sees them without a package owner.

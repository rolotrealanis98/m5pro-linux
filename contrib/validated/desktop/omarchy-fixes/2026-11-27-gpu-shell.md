# The Omarchy shell and Claude Desktop draw on the GPU (2026-11-27)
Tracker: https://github.com/rolotrealanis98/m4-m5-linux/issues/36     Kernel: 7.3.0-g0f96ca644485

## What broke
The bar's tray drawer (the `<` chevron) and the bar panels opened slowly and the motion stuttered at 120 Hz.
The Omarchy shell (Quickshell) drew every frame on the CPU: `QT_QUICK_BACKEND=software` was exported by
`~/.local/bin/hypr-session` and set again by `~/.config/environment.d/90-m5pro-quickshell.conf`. Claude Desktop still
started with `--disable-gpu` from its desktop entry and the two launchers of the work profile.

## Cause
Both were stopgaps from tracker #36 (GPU faults from Chromium-class clients took the compositor down, 2026-11-08).
The hypr-session comment read "Remove once the GPU recovery fixes land". The recovery kernel is the daily, the work
is upstream (aurora-silicon/linux #1240-#1243), and Chromium, Chrome and 1Password have run on the GPU since
2026-11-08 13:20 UTC without a recovery. The kernel journal on this machine (five boots today) holds no
"GPU work of a client failed" line. The software scenegraph cannot keep a steady 8 ms frame at 120 Hz, and with VRR
on the panel refresh follows the uneven frames, which reads as stutter.

## Fix
1. Tray drawer: `animationDuration` 600 -> 150 ms and the drawer width snapped to device pixels in the user clone
   `~/.config/omarchy/plugins/rolo.tray/Tray.qml` (personal plugin, not in this repo).
2. Runtime test: shell killed and relaunched from Hyprland with `env -u QT_QUICK_BACKEND omarchy-launch-shell`.
3. Permanent: the export removed from `hypr-session` (here: `contrib/pending/gpu/userspace/mesa-aurora/session-dcp/hypr-session`),
   `90-m5pro-quickshell.conf` moved aside (and removed from `contrib/omarchy-mac/hyprland-m5pro-profile/`),
   `--disable-gpu` removed from the three Claude Desktop launchers (copies under
   `files/2026-11-17-claude-work-profile/` updated). `systemctl --user` environment cleared for the running session.
4. Hyprland animation speeds raised in `~/.config/hypr/looknfeel.lua` (personal: windows 2.5, windowsIn 2.5, layersIn 2,
   fadeLayersIn 1.5, special workspace 2/1.5, border 3, workspaces 1.5).

## Verified
- The relaunched shell has no `QT_QUICK_BACKEND` in its environment, holds `/dev/dri/renderD128` and maps
  `libgallium` from `/opt/mesa-aurora*`; came up in about 1 s; no new aurora/asahi kernel lines after the switch.
- Rolando confirmed by eye that the shell works on the GPU ("it works great").
- Per-client audit of the session afterwards: Hyprland, the shell, Mission Control, Chrome, 1Password, Alacritty and
  muvm on the GPU; Claude Desktop was the last CPU client (`--disable-gpu`), fixed at its next launch.
- Not yet seen: a fresh login with the edited hypr-session, Claude Desktop relaunched on the GPU.
- Known unrelated warning: Quickshell built against Qt 6.12.0, system Qt 6.12.1 ("must be rebuilt").

# YouTube mini player: Chrome picture-in-picture that follows across workspaces (2026-11-19)
Tracker: https://github.com/rolotrealanis98/m4-m5-linux/issues/54     Kernel: 7.3.0-gc1e08542a544

## What broke
Nothing broke; this is a new feature. Rolando wanted a YouTube mini player that stays visible on every workspace (or on a
single one), can open by itself when he leaves a playing video, and is controlled from the Omarchy YouTube web app
(`omarchy-launch-webapp https://youtube.com/`, window class `chrome-youtube.com__-Default`, Google Chrome 158) without
another bar widget.

## Cause
- Omarchy 4.5 already treats Chrome's `Picture in picture` window as an overlay (`$OMARCHY_PATH/default/hypr/apps/pip.lua`:
  float, pin, 600x338, top right), but nothing opens one: `HTMLVideoElement.requestPictureInPicture()` needs a user gesture
  in the page, and Chrome's own automatic PiP only fires on a tab switch, not when a Hyprland workspace hides the window.
- A real key press is a gesture. Hyprland 0.57.1 (Lua config) has `hl.dsp.send_shortcut({ mods, key, window })`; sent to a
  foot window on hidden workspace 9 it delivered `ESC P` (Alt+Shift+P) and focus stayed where it was.
- Google Chrome 137+ ignores `--load-extension`: none of the extensions in `~/.config/chrome-flags.conf` (Omarchy's
  copy-url, yt-dlp, whatsapp-slim) are in the profile's extension settings. A new extension has to be loaded unpacked.

## Fix
1. `~/.local/bin/yt-pip` (Python, no dependencies beyond `hyprctl` and `playerctl`): `toggle`, `daemon`, `status`,
   `set KEY VALUE`. The daemon reads Hyprland's `.socket2.sock`, matches the Chrome MPRIS player's title to a YouTube window,
   and sends Alt+Shift+P to that window when the video plays and its workspace is not visible (auto open), and again when
   you return to it (auto close, only for a PiP it opened; a PiP you close by hand is not reopened until you go back). It
   places each new PiP window with `hl.dsp.window.pin/resize/move/set_prop(opacity)`: pinned (every workspace, follows the
   focused monitor) or unpinned on one workspace, corner, width (16:9), opacity. Settings: `~/.config/yt-pip/config.json`
   (`enabled`, `auto`, `autoClose`, `mode`, `workspace`, `corner`, `width`, `opacity`, `source`); state:
   `$XDG_RUNTIME_DIR/yt-pip.json`. Single instance (flock); exits when `enabled` is false.
2. Chrome extension `~/.local/share/yt-pip/chrome-extension` (MV3): Alt+Shift+P toggles PiP for YouTube's main video; a
   button in the player's control bar (left of the gear) toggles it on click and opens a settings panel on right-click
   (shadow DOM, built with DOM calls because YouTube enforces Trusted Types); toolbar button for normal Chrome windows;
   `mediaSession` `enterpictureinpicture` handler for Chrome's tab-switch auto PiP. The manifest carries a `key` so the ID
   stays `ccpknojkckpfdcjeopcijkoelbbcgkph` (the private key stays on the machine, `~/.local/share/yt-pip/key/`, not committed).
3. Native-messaging host `~/.local/share/yt-pip/native-host.py` + `~/.config/google-chrome/NativeMessagingHosts/io.rolo.ytpip.json`
   (and the same under `~/.config/chromium/`): `get`/`set` for the settings panel, through `yt-pip set` (validated); turning
   the helper on starts the daemon with `uwsm-app`.
4. `~/.config/hypr/autostart.lua`: `o.launch_on_start("yt-pip daemon")`; `~/.config/hypr/bindings.lua`: Super+Alt+P →
   `yt-pip toggle` (the key was free).
5. A GTK4/libadwaita settings window `~/.local/bin/yt-pip-app` (desktop entry `io.rolo.YtPip.desktop`, `NoDisplay=true`) kept
   as a fallback. An earlier bar widget (`rolo.yt-pip`) was built and removed again at Rolando's request: `shell.json` is
   back to its previous bar layout for this item.

No package installed, no kernel, boot, GPU-session or audio change.

## Verified
- `hyprctl reload` + `hyprctl configerrors`: clean; `omarchy menu keybindings --print` lists `SUPER ALT + P → YouTube mini player`.
- `send_shortcut` to a window on a hidden workspace delivered Alt+Shift+P without a focus change (foot test window, `od -c`).
- `place()` on a floating test window: pinned, 560x315, moved to the chosen corner inside the bar's reserved area, `opacity` 0.8
  (`hyprctl getprop`).
- `yt-pip status` found the YouTube web app window and its MPRIS title; one daemon runs after two starts; `enabled=false`
  stops it and `true` + start brings it back.
- Native host: `get` and `set` round-trip the config; an invalid value comes back as an error.
- `yt-pip-app` starts without errors. The extension's JS parses.
- **Not yet verified:** the PiP window opening from the player button, Alt+Shift+P or auto open, because the extension has
  not been loaded in Chrome yet (Rolando: chrome://extensions → Developer mode → Load unpacked).

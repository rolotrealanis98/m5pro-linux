# G502 X battery, DPI and polling rate from the Pointer panel (2026-11-19)
Tracker: https://github.com/rolotrealanis98/m4-m5-linux/issues/51     Kernel: 7.3.0-gc1e08542a544

## What broke
The Logitech G502 X PLUS on its LIGHTSPEED receiver (046d:c547) worked as a pointer, but nothing on the desktop could read its battery or change DPI/polling. The community plugin `morf.g502x` (Omarchy plugin marketplace) is installed and enabled but never appears: it reads the charge from `/sys/class/power_supply/hidpp_battery_*` and DPI through Solaar.

## Cause
- The running kernel has `# CONFIG_HID_LOGITECH is not set` (`/proc/config.gz`), so there is no `hid-logitech-dj` / `hid-logitech-hidpp`: the receiver's three interfaces bind to `hid-generic`, and no `hidpp_battery_*` node exists.
- `/dev/hidraw*` are `0600 root:root` with no ACL, so a user process cannot speak HID++ either; Solaar (which ships the usual udev rule) is not installed.

## Fix
1. New `~/.config/omarchy/plugins/rolo.pointer/g502.py`: a standalone HID++ 2.0 client (no Solaar, no kernel driver). It finds the receiver's vendor interface (usage page 0xFF00 with report id 0x11) in `/sys/class/hidraw`, pings device slots 1-6, and uses features 0x0005 (name), 0x1004 (unified battery), 0x2201 (adjustable DPI), 0x8060 (report rate) and 0x8100 (onboard profiles). It prints one JSON object. An flock in `$XDG_RUNTIME_DIR` keeps two runs from reading each other's replies.
2. `rolo.pointer/Panel.qml`: a third tab, **G502 X**, with battery %, charge state and bar, a DPI slider (50-DPI steps, up to 8000) plus 400/800/1600/3200/6400 presets, polling rate (125-1000 Hz), and an Onboard profiles switch. It also adds battery and DPI to the bar tooltip. When the mouse can't be reached, the tab shows the reason (no access, no receiver, mouse asleep).
3. udev rule `/etc/udev/rules.d/42-logitech-hidraw.rules` (installed by Rolando with sudo): tags Logitech hidraw nodes `uaccess`, so logind gives the seat user an ACL. The `udevadm trigger` did not apply it to the already-present receiver; replugging the receiver did.

No package installed, no kernel or boot change.

## Files changed
- `/etc/udev/rules.d/42-logitech-hidraw.rules` (new):
```
# rolo.pointer: let the logged-in user talk HID++ to Logitech receivers (G502 X tab).
# Same effect as Solaar's 42-logitech-unify-permissions.rules, hidraw only.
ACTION=="remove", GOTO="rolo_logi_end"
SUBSYSTEM!="hidraw", GOTO="rolo_logi_end"
ATTRS{idVendor}=="046d", TAG+="uaccess"
LABEL="rolo_logi_end"
```
- `~/.config/omarchy/plugins/rolo.pointer/g502.py` (new): copy in [files/2026-11-19-g502-hidpp/g502.py](files/2026-11-19-g502-hidpp/g502.py)
- `~/.config/omarchy/plugins/rolo.pointer/udev/42-logitech-hidraw.rules` (new): the plugin's copy of the rule above
- `~/.config/omarchy/plugins/rolo.pointer/Panel.qml`: G502 X tab; diff in [files/2026-11-19-g502-hidpp/Panel.qml.diff](files/2026-11-19-g502-hidpp/Panel.qml.diff) (backup `Panel.qml.pre-g502`)
- `~/.config/omarchy/plugins/rolo.pointer/manifest.json`: description mentions the G502 (backup `manifest.json.pre-g502`)

## Verified
- Before the rule: `g502.py --read` returns `{"ok": false, "error": "no-access"}`. After the replug, `getfacl` shows `user:rolo:rw-` on the receiver nodes.
- `g502.py --read` (0.15 s): `G502 X PLUS`, battery 80 %, discharging, 2450 DPI, range 100-25600 in 50-DPI steps, report intervals 1/2/4/8 ms, current 1 ms, onboard profiles on.
- `--set-dpi 2400` and then `--set-dpi 2450` both read back correctly.
- `--set-rate 2` is refused (HID++ 2.0 error 2) while onboard profiles are on: the onboard profile owns the rate. The panel now says to turn Onboard profiles off to change it. Host mode (onboard off) was not tested.
- omarchy-shell reloaded the plugin with no QML warnings. The tab's look has not been confirmed by Rolando.

## Rollback
```bash
sudo rm /etc/udev/rules.d/42-logitech-hidraw.rules && sudo udevadm control --reload   # then replug the receiver
cd ~/.config/omarchy/plugins/rolo.pointer
cp -a Panel.qml.pre-g502 Panel.qml && cp -a manifest.json.pre-g502 manifest.json   # also drops the later Quit-menu edit
rm -r g502.py udev
```

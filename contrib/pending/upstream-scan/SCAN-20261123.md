# Upstream scan for the J716s, 2026-11-23

Read-only research plus local `git merge-tree` dry runs. Nothing pushed, nothing filed upstream, no builds, no MacBook access.
"Applies" means a textual cherry-pick simulation; **nothing here was compiled** (the build container was busy), so every "grab now"
needs one kernel build and a boot before it is trusted. Rust (`drm/asahi`) changes are the most likely to apply cleanly and still not build.

| Loader | aura `j716s-fix1` 16ab9c11 / `j716s-camera-1` 191168bb on base `52af355c` (2026-11-14); upstream main `efe821f5` is 378 commits ahead |
| Mesa | `/opt/mesa-aurora` = `a79e5a94e316`; aurora-wip tip is `efabab385` (527 commits past our 11-17 build) |

Dry-run method: every one of the 318 merged PRs was tested alone (`git merge-tree --write-tree --merge-base=<PR fork point> j716s-ane2293 <PR head>`),
172 apply cleanly, 144 conflict, 2 are already in. Then 71 chosen PRs were applied in merge order, each on top of the last, via
plumbing (`git commit-tree`): **all 71 apply in sequence**. The result is a throwaway ref in `/Volumes/m5pro/linux`:
`refs/scan/stack-20261123` (tip `8fb9d5d555cd`; no branch, no worktree, not pushed). Open PR heads are fetched as `refs/scan/pr/<N>`.
The stack is a superset for testing (it includes #2535 Mac Studio audio, #2507, #2261, which are not recommendations).
